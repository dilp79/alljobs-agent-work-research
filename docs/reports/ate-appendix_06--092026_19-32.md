# ATE: что покрывает опубликованный каталог и как он связывается с AllJobs

Это приложение воспроизводит описательные агрегаты **CohereLabs/ATE**, revision
`4b567ba98acc6ddf27b2abb9004844581083c5d8`, и отдельно проверяет идентичность задач в локальном
AllJobs. Метка `good` относится к сопоставлению **описания инструмента** и ближайшей задачи.
Здесь не измеряются вызываемость инструмента, успешность исполнения, внедрение или ROI.
Новые модели, внешние ATE-серверы и человеческая разметка не использовались.

## Публичный источник и воспроизведение

Проверены все восемь используемых Parquet-таблиц, суммарно около 209,6 MB. SHA-256 каждого
файла совпадает с [MANIFEST фиксированной версии](https://huggingface.co/datasets/CohereLabs/ATE/blob/4b567ba98acc6ddf27b2abb9004844581083c5d8/MANIFEST.json);
сам MANIFEST закреплён SHA-256
`bcd60bb94d625cdc73cc988ae4c5c245c0a7957f1356b288f4e8ce596fa9cb35`.
Таблицы Hub лежат под `data/<table>/train-00000-of-00001.parquet`, тогда как MANIFEST
называет исходные `<table>.parquet`; скрипт явно задаёт соответствие этих путей. Совпадение
байтов доказывает целостность скачанных данных, а не воспроизводимость неопубликованного
процесса их получения. Контекст и описание полей: [dataset card](https://huggingface.co/datasets/CohereLabs/ATE/tree/4b567ba98acc6ddf27b2abb9004844581083c5d8),
[data dictionary](https://huggingface.co/datasets/CohereLabs/ATE/blob/4b567ba98acc6ddf27b2abb9004844581083c5d8/DATA_DICTIONARY.md),
[статья Cohere](https://cohere.com/blog/automations-early-footprint).

В каталоге `workforce-graph`:

```bash
uv sync --locked --python 3.14.7 --extra dev
# Только эта явно выбранная команда использует сеть; сырьё хранится вне репозитория.
uv run python scripts/reproduce_ate_audit.py fetch
# Дальнейший анализ работает офлайн с проверенным пользовательским кэшем.
uv run python scripts/reproduce_ate_audit.py audit --output /tmp/ate-descriptive.json
```

Кэш по умолчанию — `~/.cache/alljobs/ate/<revision>`. Для уже загруженных файлов передайте
`--cache <каталог>` в обе команды. Исправные файлы переиспользуются без сетевого запроса;
чужая версия, повреждённые байты и существующий несовпадающий output вызывают отказ.
Raw-кэш внутри репозитория запрещён. Скачанные файлы не входят в это приложение.

## Знаменатели, которые нельзя смешивать

| Показатель | Пересчитано |
|---|---:|
| Server listings | 123 069 |
| Listings с извлечёнными tools | 70 929 |
| Строки tools / строки analysis set | 696 291 / 694 411 |
| Rank-1 пары / пары с заполненной меткой | 694 411 / 694 406 |
| Пропуски match_quality | 5 |
| `good` / `partial` / `bad` | 18 058 / 591 826 / 84 522 |
| Все task IDs / software-eligible IDs | 18 796 / 9 423 |
| IDs с хотя бы одним `good` | 1 380 |
| Все occupations / software-eligible / с `good` | 923 / 895 / 491 |
| Eligible occupations без `good` | 404 из 895 |

Таким образом, **2,600496%** — доля `good` среди **694 406 размеченных пар**, а
**14,645018%** — покрытие **1 380/9 423 task nodes**. Доля `good` среди всех rank-1 строк,
включая пять пропусков, равна 2,600477%. Это разные вопросы. Покрытие обусловлено
software-performable classification, выбором одного ближайшего кандидата на инструмент и
модельной меткой `good`. Оно не является долей рабочего времени или успешно выполненных задач.

Восемь occupations имеют 100% такого покрытия; у всех меньше трёх eligible tasks. Среди
786 occupations с минимум тремя eligible tasks полностью покрытых нет. Всего без `good`
432 occupations, если включить 28 occupations без eligible tasks; этот знаменатель отличается
от 404/895.

У tools **49 142 пустых описания** при нуле SQL-null описаний. Для ID нужно ещё одно
различение: **1 876 повторов непустых tool IDs**, **три SQL-null ID**, 694 412 различных
непустых ID. Прежний pandas `duplicated()` давал 1 878, включая два повторения null; это
не 1 878 повторов содержательных идентификаторов. У task text есть **398 групп одинаковых
текстов** и **1 260 лишних строк относительно уникальных текстов**, хотя task IDs уникальны.
Поэтому text-only join может смешивать разные occupational nodes.

[Полный оригинальный агрегат с хэшами источников](../../workforce-graph/data/ate_audit/descriptive.json)
дополнительно содержит размеры таблиц и taxonomy counts: 1 139 occupational clusters,
из них 693 subatomic, 411 composite и 35 new. Это результаты той же фиксированной версии,
а не обновление исходного каталога и не новая разметка его качества.

## Отдельный локальный join с AllJobs

ATE использует O*NET 29.2; конфигурация данного AllJobs checkpoint — O*NET 30.2.
Версия AllJobs задана source configuration, а не выведена независимо из произвольного DuckDB.
Сопоставление сначала использует точное равенство `ATE.task_id = curated.activity.source_code`
при `source_system='onet'` и `activity_type='task'`, затем отдельно проверяет текст и SOC.
Тексты не нормализуются и не сопоставляются нечётко.

| Проверка | Результат |
|---|---:|
| Exact task-ID matches | 18 775 |
| Только ATE / только AllJobs IDs | 21 / 21 |
| Совпадающий текст / изменившийся текст среди matched IDs | 18 770 / 5 |
| Совпадающий staging SOC / расхождение или отсутствие | 18 775 / 0 |
| Matched IDs без task→occupation edge в curated | 845 |
| ATE software-eligible IDs, сохранившиеся в AllJobs | 9 416 из 9 423 |
| `good`-поддержанные task IDs, сохранившиеся в AllJobs | 1 379 из 1 380 |

Для 845 задач SOC подтверждается в `staging.stg_onet_task_statements`, хотя curated edge
отсутствует. Join только через curated occupation relation потерял бы эти совпадения.
Текст изменился у task IDs `1638`, `1641`, `18000`, `18493`, `18494`; наблюдаются небольшие
редакционные изменения, однако различие версий сохраняется явно.

Миссии связываются **только через принятый post-review effective_candidate_bindings.csv**,
закреплённый отдельным SHA-256 в скрипте. Все 120 effective mission activities присутствуют
в локальном task corpus и ATE; **55 из 120** имеют хотя бы один `good` descriptor match.
У всех 120 исходная кандидатная activity была заменена review. Старый filename и переименованные
непринятые байты отказываются, даже если их IDs могли бы правдоподобно соединиться с корпусом.
Эти 55 совпадений **не подтверждают успешность миссий** и не меняют выбранные другим протоколом
три семейства задач.

Локальная команда требует закрытых входов и не является обещанием их наличия в public clone:

```bash
uv run python scripts/reproduce_ate_audit.py join-alljobs \
  --database data/workforce_graph.duckdb \
  --effective-bindings benchmark/support_backoffice/v1/effective_candidate_bindings.csv \
  --output /tmp/ate-private-join.json
```

[Агрегированный локальный receipt](../../workforce-graph/data/ate_audit/private_join.json)
содержит численности, task-ID inventories и хэши исходных/логических входов, но не DB rows,
task text или private binding rows. Публично воспроизводимая часть — ATE cache → агрегаты.
Private join можно повторить только при наличии соответствующих исходных AllJobs inputs.

## Граница распространения и вывода

Исходный пакет не объявляет общей лицензии на весь ATE. O*NET text и verbatim tool descriptions
имеют свои права; доступность файлов не означает разрешение перелицензировать их целиком.
Это приложение содержит оригинальный код, агрегаты, идентификаторы и хэши. Parquet-таблицы,
tool descriptions, task text, заметки о разметке, PDFs и закрытые AllJobs строки не
перераспространяются. Пользователь получает источник напрямую у его владельца.

`good` пригоден для выбора гипотез и кандидатов. Он не доказывает доступность сервера,
совместимость разрешений, выполнение полного назначения задачи или экономическую пользу.
Отсутствие `good` при rank-1 поиске также не доказывает отсутствие подходящего инструмента.
Для следующего эксперимента эти различия должны проверяться по наблюдаемым вызовам и
заранее заданным предметным критериям, а не по ещё одному пересказу descriptor labels.
